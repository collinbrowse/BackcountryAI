# BackcountryAI

An iOS app (SwiftUI, MLX) whose Xcode project is generated by XcodeGen from `project.yml`. After changing
`project.yml`, run `xcodegen generate` and commit `BackcountryAI.xcodeproj` with it. Release pipeline, CI and every
fastlane lane: `docs/release.md`. Library, answer quality and model work: the other files in `docs/`.

## This Mac is shared

Several Claude sessions run at once, each in its own worktree under `.claude/worktrees/`, beside the self-hosted CI
runner. Builds, tests and ML jobs go through one machine-wide queue (`~/.claude/bin/slot`, used by
`scripts/queue.sh`, the Fastfile and the `xcodebuild` shim), so:

- A heavy command may print `slot: queued for 4 of 10 CPU credits ...` and wait, sometimes for many minutes. That's
  normal: it starts by itself. Don't kill it, retry it or work around the queue. Give such commands a long Bash
  timeout (up to 600000 ms) or run them in the background.
- `~/.claude/bin/slot status` shows what's running and waiting.

## Unit tests

```bash
bundle exec fastlane test                                          # all of them
bundle exec fastlane test only:BackcountryAITests/LLMEngineContractTests   # one suite (commas for several)
```

First time in a worktree: `bundle config set --local path vendor/bundle && bundle install`. The first build in a
worktree compiles MLX from scratch (about 4 minutes on a quiet Mac, much longer under load); later ones are
incremental. The full log is `build/test.log`.

The lane queues the build, builds into `build/DerivedData`, takes the Swift packages from a cache shared by every
worktree (`scripts/spm-cache.sh`) and runs on this worktree's own simulator (`scripts/simulator.sh`). If you run
`xcodebuild` yourself, do the same:

```bash
xcodebuild -project BackcountryAI.xcodeproj -scheme BackcountryAI \
  -destination "platform=iOS Simulator,id=$(scripts/simulator.sh)" \
  -derivedDataPath build/DerivedData $(scripts/spm-cache.sh --xcode-flags) \
  -skipMacroValidation -skipPackagePluginValidation test
```

- Always `-derivedDataPath build/DerivedData`, never a path in a session scratchpad or `/tmp`: a fresh one means a
  cold MLX build.
- Use this worktree's simulator ("BackcountryAI <worktree folder>", from `scripts/simulator.sh`), not the shared
  "iPhone 18 Pro Max": every worktree installs the same bundle id, so on a shared simulator they replace each
  other's app mid-test. It is shut down when the worktree goes idle and deleted with the worktree.

## Heavy library and MLX jobs

`scripts/build-library.sh`, `embed-library.sh`, `check-answers.sh`, `train-answers.sh`,
`tools/train-answers/train.sh`, `tools/train-answers/answer_mlx.py` and `tools/model-eval/run_mlx.py` queue
themselves. MLX jobs (and `check-answers.sh`, which uses Apple's on-device model) also hold the queue's `mlx` lock, so
only one runs at a time: two MLX jobs swap the Mac, and one beside Apple's model makes every request fail. Run them
through those scripts, not around them. Anything else heavy: `scripts/queue.sh --credits 4 -- <command>`, adding
`--lock mlx` if it uses MLX or Apple's model.
`library/build_library.py` uses `LIBRARY_WORKERS` processes (default 4).
